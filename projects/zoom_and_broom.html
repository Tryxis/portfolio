Zoom and Broom

.NET microservices application

Part of an on-going learning course to build an auction site for cars. Built with .NET 8, Next.js, IdentityServer and RabbitMQ, and currently running via Docker.

APIIn progress
View Repo

Build notes

Separate services, separate stores

The auction service owns its data in Postgres; the search service keeps its own read-optimised copy in MongoDB. Each picks the database that suits its job instead of sharing one and pretending the services are independent.

Kept in step by messages

Auction created, updated and deleted events are published to RabbitMQ and consumed by search. The event contracts live in a shared project so both ends compile against the same definition and a breaking change fails the build rather than production.

Identity as its own service

Authentication is a service in its own right rather than a concern bolted onto each API, which is what makes adding the next service cheap.

The whole stack comes up with one command

Postgres, MongoDB and RabbitMQ are all declared in docker-compose, so a clean machine goes from checkout to running system without a setup document.
